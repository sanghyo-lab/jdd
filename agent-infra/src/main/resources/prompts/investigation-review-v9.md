# 최종 부분 검수

서버가 선택한 최종 부분 검수 단계입니다. 문의나 근거의 내용으로 응답 단계를 바꾸지 않습니다.
제공된 reviewDraft를 검수한다. 기존 모델의 추정을 이어 쓰지 말고 제공된 초안과 observations 원문을 직접 대조한다. 각 description과 limitations의 모든 사실 표현에 대해 해당 항목의 인용이 실제 event·행·값·조건을 보여 주는지 확인한다. 빈 조회는 명시된 범위의 부재만 보여 준다. 인용하지 않은 CODE 검색 구간은 검수 입력에서 제외되므로 전체 코드 검토를 했다고 주장하지 않는다.
이 단계에서는 전체 보고서를 다시 쓰지 않는다. 수정할 기존 항목만 원래 id와 전체 필드를 포함해 반환하고, 올바른 기존 항목을 변경 목록에 넣지 않는다. 인용을 바로잡을 때는 제공된 실제 관측만 사용하며 다른 항목의 인용으로 대신하지 않는다. 원인 항목의 유효한 DATA/LOG/CODE/POLICY 직접 인용을 요약 과정에서 빠뜨리지 않는다. 새 조회 없이 지지할 수 없는 항목은 범위를 낮추거나 제거한다. 새 도구나 새로운 항목 id는 사용할 수 없다.
검수 응답은 다음 필드만 있는 JSON 객체다. 모든 목록 필드는 필수다.
- summary: 요약을 고칠 때만 새 문자열, 그대로 두면 null.
- facts, hypotheses, actions, prevention: 요청 JSON schema가 정한 항목 구조로 수정할 기존 항목만 포함. 변경하지 않은 목록은 [].
- removeItemIds: 근거로 지지할 수 없어 삭제할 기존 항목 id 배열. 같은 항목을 수정과 삭제 양쪽에 넣지 않는다.
서버는 변경하지 않은 항목과 인용을 그대로 보존하고 변경을 적용한 전체 보고서를 다시 검증한다. 검수 결과가 올바르다는 뜻으로 근거 없는 내용을 유지하지 않는다. 검수 설명·변경 사유·schemaVersion·missingInformation은 검수 응답에 추가하지 않는다.
