## 결정할 질문

데모 전체 $30을 넘기지 않도록 Agent PC $5, VOC PC $10, commerce·lead PC 합산 $15를 배분하고 아래 범위로만 실제 모델 검증을 준비할 것인가?

## 배경과 확인 근거

- [데모 정책](../planning/demo-llm-policy.md)과 [비용 계획](../planning/llm-efficiency-plan.md)은 공유 예산·리더의 새 검증·미확정 비용을 포함한다. $50 프로모션 표시는 $30 제한 확대나 개발용 사용 허가가 아니다.
- `1e179f3`의 Agent는 재시작·새 키·모델 변경으로 초기화할 수 없는 설치별 영속 장부, USD 상한·총 호출 수·조사별 호출 수·동시 수를 구현했다. 공용 원격 장부는 구현하지 않았다. 세 PC에 각각 $30을 설정하면 팀 전체 제한을 지킬 수 없다.
- `0ba2862`까지 모의 모델/실제 커머스 근거 검증과 전체 publish를 통과했다. 실제 모델 접근·품질·토큰/비용, VOC/web/ngrok는 미검증이다. 이 제안은 사용자의 승인이나 다른 담당자의 배분 수락을 대신하지 않는다.
- 키의 조직/프로젝트·프로모션 연결, 남은 잔액/기간, 다른 PC의 실제 장부는 직접 확인하지 않았다. API 키 값은 이 논의에서 요청하거나 기록하지 않는다.

## P1 제안과 대안

### 배분과 범위

| 실행 PC / 역할 | 데모 누적 USD 상한 | 실제 HTTP 시도 총상한 제안 | 대상 |
| --- | ---: | ---: | --- |
| 한재홍 / Agent | 5 | 88 | VOC-01~07·NORMAL·NEEDS_INPUT·IDEMPOTENCY·RECOVERY 11종 데모 검증 |
| 김아름 / VOC | 10 | 88 | 같은 11종의 실제 VOC/web 통합 검증 |
| 이상효 / commerce·lead | 15 | 176 | commerce 담당 11종과 별도 리더 11종 검증을 같은 장부에서 합산 |

- 호출 수는 목표가 아닌 최대 허용 시도다. 같은 키 재전송·조회/새로고침·근거 조회에는 0회, 새 조사·실패한 시도·보고서 수정을 포함한 모든 실제 HTTP 호출은 누적한다. 11개 case가 반드시 11개의 새 유료 조사를 뜻하지 않는다.
- 각 PC는 하나의 영속 DB/장부와 고유 scope를 사용한다. 검증 clone·DB를 새로 만들어 배분을 복제하지 않는다. commerce와 lead를 분리 배분하거나 장부를 초기화하지 않는다.
- 최초 후보는 `gpt-5.6-luna`, reasoning low, 조사당 최대 8회·180초, 출력 호출당 최대 4,096, 동시 유료 호출 1이다. 다른 모델 자동 전환은 없다. 모델 품질을 통과하기 전 최종 모델로 확정하지 않는다.
- 승인 뒤의 명시적 프로필은 최대 24시간만 유효하다. 기간 연장은 같은 scope/장부/배분을 유지하며 실제 데모 범위를 다시 확인한다. 예제의 만료값을 미리 활성 시각으로 바꾸지 않는다.
- 2026-09-21 버전 가격과 전체 모델 입력 상한으로 예약하는 Luna 호출당 최대치는 $0.5323728이다. 88회를 모두 최대치로 소비하면 $46.8488064이므로 **호출 수만으로 예산을 보장하지 않는다**. 매 호출 전 확정+미확정+예약+새 호출 최대치를 검사해 해당 PC 배분을 넘을 호출을 차단한다. $5 안에서 모든 case를 완료할 수 있다는 보장은 없다.
- 실측 비용·지연·정답 품질을 기록해 성공 조사당 총비용을 평가한다. 미확정 usage는 0으로 채우지 않는다. 한도 때문에 완료하지 못한 case는 실패/미검증으로 남긴다. 중단한 호출의 예약액을 임의 환급하지 않는다.

### 실행 순서와 책임

1. 세 담당자가 배분·동일 장부 사용을 직접 답변한다. 필요한 다른 배분은 총합 $30 이하인 새 제안으로 합의한다.
2. 한재홍은 사용자가 승인한 서비스 데모 범위와 로컬 비밀 파일 경로를 확인한다. 키 값은 브라우저/문서/로그에 넣지 않는다. 남은 API 접근 조건은 실제 확인 전 가정하지 않는다.
3. 각 PC의 기존 장부·QUEUED/RUNNING·프로필을 확인한다. 첫 VOC-07은 수동으로 실행하고 응답 모델·usage·보고서 근거를 검토한다. 미확정 과금이나 실패가 있으면 원인을 기록하고 다음 유료 호출을 중단한다.
4. 준비된 나머지 데모 case를 순차 실행한다. 반복 커머스 재현은 별도로 수행하며 일반 check/publish/CI·원격 상태 확인에서 유료 실행을 하지 않는다. UI가 준비되기 전의 로컬 API 검증과 ngrok PC/모바일 검증을 구분한다.
5. 실제 완료 기록은 최신 필수 검증과 내용 해시에 맞춰 담당자가 작성한다. 선택 메타데이터의 DTO·전달 경로는 [DISC-20260921-voc-001](DISC-20260921-voc-001-runner-metadata.md) 결정대로 별도 합의하며 새 필수 완료 필드를 만들지 않는다.

- 대안: 중앙 비용 장부를 새로 구현하면 다중 PC 배분 변경은 유연하지만 공통 운영 기반이 더 필요하다. 현재 P1은 이미 구현한 설치별 장부와 명시적 배분으로 진행한다.
- 합의 전 독립 작업: 모의 모델·실제 PostgreSQL·상대 구현/정책 사본·web 검증, 실패 기록과 검증용 관측 내보내기 준비. 실제 키/모델은 활성화하지 않는다.
