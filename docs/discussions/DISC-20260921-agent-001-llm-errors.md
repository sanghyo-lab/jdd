## 배경과 확인 근거

- [현재 계약](../integration-contract.md)의 ApiError는 code/message/retryable이며, 조사 GET은 실패 조사도 HTTP 200으로 반환한다. 접수 전달 실패와 조사 실패는 별도다.
- [데모 정책](../planning/demo-llm-policy.md), [비용 계획](../planning/llm-efficiency-plan.md), agent 상태의 오류 매핑 요청과 김아름의 `JDD-VOC-003`를 구체화한다. 확인한 원격은 `b2b46ef`(부모 VOC 착수 `f466d37`)다.
- 현재 접수 API는 유료 모델을 호출하지 않는다. 실제 모델 실패 재현은 아직 수행하지 않았다. 아래 P1은 전원 수락했으며 구현·검증은 남아 있다.
- 합성 검증: 모의 모델 설정 누락, 401/403, 429/5xx, 응답 시간 초과, 비용 예약 거절을 주입한다. 기대는 GET의 FAILED/error 표시, 기존 근거 유지, 조회·같은 키 재전송의 추가 모델 호출 0회다.

## P1 제안과 대안

| 외부 code | 내부 원인 예시 | retryable | 화면의 후속 조치 |
| --- | --- | --- | --- |
| LLM_CONFIGURATION_ERROR | 유료 실행 비허용, 필수 모델/가격/범위 미설정, 인증·모델 접근 거절 | false | 운영 설정 확인. 사용자 입력 부족으로 표시하지 않음 |
| LLM_UNAVAILABLE | 한도 내 재시도 후 429/5xx·연결 실패·개별 모델 응답 시간 초과 | true | 일시 장애 표시. 설정·예산 확인 후 사용자가 새 키로 재조사 가능 |
| INVESTIGATION_BUDGET_EXCEEDED | 영속 장부의 새 호출 비용 예약 거절, 조사별 토큰/호출 한도 소진 | false | 사용량/허용 범위 확인. 새 키나 재시작으로 예산 초기화 금지 |

- 위 오류는 접수 202 이후 조사 FAILED/error에 사용한다. 조사 전체 시간 초과는 기존 INVESTIGATION_TIMEOUT, 재시작 중단은 INTERRUPTED를 유지한다.
- retryable=true는 자동 실행 허가가 아니다. FAILED 조사 자체는 같은 키로 다시 실행하지 않으며, VOC는 기존 실패와 근거를 조회한다. 새 유료 조사는 명시적인 새 키 접수와 Agent의 예산·실행 허용 검사 후에만 가능하다.
- VOC의 AGENT_UNAVAILABLE 및 submissionError는 기존대로 유지한다. syncError 때문에 저장된 조사 상태를 바꾸지 않는다.
- 미지의 code도 message와 code를 일반 오류로 표시하고 보고서 화면을 깨뜨리지 않는다. 원문 provider 오류·API 키·요청 헤더는 사용자 응답에 넣지 않는다.
- 대안: 세 원인을 INTERNAL_ERROR 하나로 반환하면 v1 코드 목록은 유지되지만 운영자가 인증·장애·예산을 구별하기 어렵다. 그래서 필드·상태 변경 없는 코드 추가를 권고한다.
- 적용 순서: VOC 미지 코드 기본 표시와 모의 화면 검증 → 명시적 합의 → agent가 계약 표와 매핑 구현 → 합성 실패 HTTP/화면 검증. commerce 업무 API·정상 정책은 변경하지 않는다.
- 합의 전 독립 작업: Agent 영속 선점·근거 저장·보고서 검증·비용 장부, VOC 접수/조회와 일반 오류 표시. 현재 계약을 조용히 변경하지 않는다.
