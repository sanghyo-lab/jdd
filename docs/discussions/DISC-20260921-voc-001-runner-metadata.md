## 배경과 확인 근거

- 원문: [비용 계획](../planning/llm-efficiency-plan.md)의 runner 확장 제안, [연동 위험 검토](../planning/agent-integration-risk-review.md), 로컬 협업 항목 JDD-VOC-008. 확인한 원격은 `943e961`이다.
- `scripts/jdd.py`의 validate_mvp_result는 buildId·mode·model·필수 case와 실제 검증 여부를 검사한다. 세 제안 필드는 현재 필수가 아니다. [팀 완료 기준](../team-completion.md)을 임의로 바꾸지 않는다.
- Agent의 비용 장부 구현이 공유됐지만 runner에 전달할 관측 DTO·조회 경로와 최종 모델 표시는 아직 이 건에서 합의하지 않았다. 계획·설정 값을 실제 사용량으로 취급하지 않는다.
- 이 건은 선택적 관측 확장의 범위 결정이며 기존 티켓·Agent 접수·7개 VOC 구현을 차단하지 않는다. 실제 모델 호출·비용 측정은 수행하지 않았다.

## P1 제안과 대안

- 권고: 기존 필수 model 문자열은 실제 최종 모델을 기록한다. 임의의 라우터 이름이나 설정상 후보 모델을 실행 모델로 기록하지 않는다. 현재 완료 검사와 역할 JSON에는 새 필수 항목을 추가하지 않는다.
- 선택적 modelsUsed는 실제 관측된 모델만 포함한다. usageSummary는 확인된 사용량·비용과 미확정 부분을 구분하며 알 수 없는 값을 0으로 채우지 않는다. verificationProfileId는 비밀 값 없는 평가 설정의 지문이며 buildId나 코드 내용 해시를 대체하지 않는다.
- 위 항목의 실제 DTO·수집 경로·단위·누락 표현은 제공자와 소비자가 후속 제안으로 확정한 뒤 구현한다. 현 단계에는 세 필드 생성과 필수 판정 추가를 보류한다. 추가 정보를 모으기 위한 유료 호출도 하지 않는다.
- 대안: 지금 세 필드를 필수로 승격하면 Agent 관측 제공·runner·공통 검사·세 역할 JSON·리더 검증을 동시에 바꿔야 한다. 기존 MVP 구현을 기다리게 할 이유가 없어 채택하지 않는다.
- 독립 진행: 김아름은 기존 runner 계약과 순차 시나리오를, 한재홍은 실제 비용 장부·호출 보호를, 이상효는 기존 필수 검증과 commerce 재현을 진행한다.
