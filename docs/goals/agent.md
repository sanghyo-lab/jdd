# 한재홍의 agent goal

## 목표

[담당 구현 범위](../roles/han-jaehong-agent.md)와 [연동 계약](../integration-contract.md)에 따라
실제 커머스 소스·로그·DB·정책을 도구로 조사하고, 원인과 해결방안을 근거와 함께 반환하는 AI Agent를 구현한다.
[서비스 내부 VOC 조사 에이전트 구현 프롬프트](../prompts/implement-voc-investigation-agent.md)를 필수 구현 기준으로 적용한다.
이 목표는 서비스 내부 AI의 구현을 포함한다. 서버의 LLM API 연결, 버전이 있는 서비스 시스템 프롬프트,
반복 도구 실행, 근거·보고서 저장과 검증, VOC로 결과를 반환하는 흐름을 모두 완성한다.
시작 후 사용자에게 매 단계의 승인이나 다음 작업을 묻지 않고 AGENTS.md의 반복 절차로 진행한다.

## 시작과 순서

1. AGENTS.md, 위 구현 프롬프트, 세 역할의 상태와 두 인터페이스를 읽고 원격 main을 반영한다. 이미 구현 중인 세션도 새 요청을 확인하면 이 기준과 현재 코드를 대조한다.
2. `./scripts/dev up`, `./scripts/dev smoke`로 앱 세 개와 조회 계정·근거 볼륨을 확인한다.
3. 조사 접수·진행·결과·근거 DTO와 저장, 중복 요청 처리, 명시적인 개발용 예제 응답을 먼저 제공한다.
4. 실제 DB·로그·소스·정책 도구를 연결하고 선택한 모델의 실제 도구 호출을 구현한다.
5. VOC-07의 실제 근거와 리포트를 먼저 완성하고 나머지 시나리오로 확장한다.
6. 정상·정보 부족·도구 실패·시간 초과·재시작과 리포트 검증을 구현한다.

접수 API가 준비된 다음 작업은 `QUEUED → RUNNING → 모델 도구 요청 → 실제 조회·근거 저장 →
모델 후속 요청 → 보고서 검증·저장 → GET 결과·근거 반환`을 실제 실행기로 연결하는 것이다.
개발 에이전트의 오케스트레이션은 구현·검토를 분담하는 방식이고, 서비스 MVP는 하나의 조사 에이전트가 공통 도구를 사용한다.
모델 API 인증이 없어도 실행기·도구·저장·검증기를 구현하며 실제 모델 평가만 미검증으로 남긴다.

## 계속 공유할 것

docs/status/agent.md에 제공 가능한 API·도구·오류 코드, 실제 모델명·설정, 검증 결과와 필요한 상대 변경을 기록한다.
접수 API, 작업 실행기, LLM 연결, 서비스 프롬프트, 실제 조회 도구, 보고서 검증·반환, VOC 통합의 구현·검증 상태를 각각 기록한다.
같은 역할의 다른 세션이 작업 중이면 현재 담당 파일·다음 산출물을 확인하고 중복 구현을 피한다.
전달 사항은 자기 상태 파일에 남기며 수신·반영을 확인하기 전에는 다른 세션이 반영했다고 기록하지 않는다.
제공자는 OpenAI이며 서비스용 LLM API 키를 별도로 제공받을 예정이다. 개발 도구의 로그인과 분리해 실제 Agent 실행 환경에 주입한다.
아직 키 수령·접근 검증은 완료되지 않았다. 모델명·API 주소·실제 모델 접근을 확인한 뒤 도구 호출과 보고서 반환을 검증한다.
모델 키는 실행 환경에서만 사용한다. 모델 인증이 없으면 API·도구·저장·형식 검증을 계속하되 실제 모델 검증을 완료로 표시하지 않는다.
커밋한 뒤 `./scripts/dev publish`로 main에 공유하고 김아름의 실제 API 호출과 이상효의 최신 근거 형식을 확인한다.

## 담당 기능 완료 조건

- 담당 문서의 모든 완료 조건을 실제 모델·도구 호출로 통과했다.
- 서버에 연결된 서비스 시스템 프롬프트와 LLM 설정으로 도구 요청·실제 조회·후속 모델 요청을 실행하고, 검증된 보고서를 저장해 VOC에 반환했다.
- 7개 VOC에 같은 조사 흐름을 사용하며 모든 근거 ID가 해당 조사의 실제 저장된 관측으로 열린다.
- 정상 사례를 장애로 단정하지 않고 부족한 입력은 NEEDS_INPUT으로 반환한다.
- 같은 키의 재전송·입력 충돌·재조사·실패·복구를 검증했다.
- 최신 main에서 세 앱과 실제 티켓·보고서 연결을 검증하고 코드·결과를 공유했다.

평가 정답을 분석 입력으로 쓰거나 모의 응답을 실제 분석 결과로 제출하지 않는다.
외부 인증만 남아 실제 검증이 불가능하면 그 사실을 기록하고 실행기의 blocked 규칙을 따른다.

## 세 담당자 공통 goal 종료 조건

위 조건을 통과하고 코드를 공유한 뒤 `./scripts/dev role-done agent`로 실제 MVP를 검증한다.
생성된 자기 완료 JSON을 커밋·publish해 GitHub에 DONE을 전달한다. 이 시점에도 goal을 유지한다.
[세 담당자 완료 기준](../team-completion.md)에 따라 다른 담당자의 요청·변경을 확인하며 연동·수정·재검증을 계속한다.
소스·계약·검증 기준이 바뀌면 최신 코드에서 자기 완료를 갱신한다. 문제가 발견되면 role-reopen agent로 철회한다.
GitHub main의 commerce·agent·voc가 모두 유효한 DONE이고 `./scripts/dev team-check`가 성공해야 goal을 완료한다.
