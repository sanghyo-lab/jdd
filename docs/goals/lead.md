# 이상효의 개발리더 최종 검증 단계

이 문서는 [commerce goal](commerce.md)의 후속 책임이다. 이상효는 같은 세션에서 커머스 구현과 개발리더를 겸한다.
별도 담당자나 별도 goal을 시작할 필요가 없다. 다른 두 담당자의 goal은 리더 최종 승인이 공유될 때까지 유지한다.

## 목표

세 담당자의 완료 선언을 출발점으로 삼아 전체 코드와 실제 실행을 독립적으로 검사하고,
발견한 문제를 수정·보완해 검증된 프로젝트만 최종 완료한다. [리더 책임과 기록 형식](../roles/lee-sanghyo-lead.md),
[공통 품질·종료 기준](../team-completion.md), AGENTS.md를 적용한다.

## 반복 절차

1. 구현 중에도 전체 변경·계약·리더에게 온 요청을 확인한다. 자신의 commerce 구현도 검토 대상에 포함한다.
2. 최신 main의 세 담당자 완료가 모이면 roles-check로 최종 검토의 입력을 확인한다.
3. 전체 영역의 실제 코드·테스트·마이그레이션·설정을 읽고 계약과 실행 경로를 대조한다.
4. 자기 PC의 세 앱·실제 PostgreSQL·모델·화면으로 전체 흐름을 직접 실행한다.
   초기화와 데이터 격리, 반복 재현, 정상·예외·재시도·복구, 근거·리포트 일치를 확인한다.
5. 문제를 LEAD ID로 기록하고 직접 수정하거나 담당자에게 재현 근거와 함께 요청한다.
   수정 후 관련 회귀 검증을 실행하고 공유한다. 변경된 코드에 대해 각 담당자의 DONE 갱신을 확인한다.
6. 모든 필수 검사를 통과하고 미해결 지적이 없으면 docs/status/lead-review.json과 lead.md를 작성·공유한다.
7. lead-approve를 실행해 전체 MVP를 다시 검증하고 생성된 lead.json을 커밋·publish한다.
8. 최신 main에서 team-check가 성공하고 알려진 미해결 문제·필수 검증 누락이 없을 때만 goal을 complete로 처리한다.

세 담당자의 DONE만으로 종료하지 않는다. 기존 성공 로그의 재사용, 미검토 영역 생략, 실패한 테스트 약화,
모의 응답이나 근거 없는 PASSED 기록으로 완료하지 않는다. 예상 시간이 지나도 같은 기준을 유지한다.
외부 인증·실행 환경 때문에 검증할 수 없으면 완료하지 않고 실제 사유를 기록하며 실행기의 blocked 규칙을 따른다.
