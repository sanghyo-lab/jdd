# 데모용 OpenAI 키·비용·로컬 실행 규칙

2026-09-21 사용자 지시를 반영한다. 이 문서는 구현 요구와 사용 범위를 정하며 런타임 차단 구현 완료를 뜻하지 않는다.
키 값은 이 문서·코드·Git·로그에 넣지 않는다. 전달된 키는 이번 작업에서 저장·설정·호출하지 않았다.

## 사용 범위

사용자는 데모 비용을 GS 해커톤에서 전달받은 OpenAI API 프로모션 크레딧으로 충당하는 방향으로 변경했다.
프로모션 코드는 API 인증 키의 대체값이 아니다. 앱에는 크레딧이 적용되는 조직·프로젝트의 API 키를 별도로 사용한다.
기존 키가 해당 조직·프로젝트에 속하는지 확인하며, 프로모션 수령만으로 기존 키의 적용 가능 여부를 확정하거나 재발급을 필수로 요구하지 않는다.
API 키와 프로모션 코드 원문은 문서·Git·로그에 남기지 않는다. API 키만 실제 데모 실행 환경의 비밀 설정에 주입한다.

- OpenAI 키는 서비스 데모용이다. 개발 에이전트, 코드 생성, 일반 개발 테스트, CI, 반복 평가에 사용하지 않는다.
- 개발은 네트워크 없는 모의 모델과 합성 응답으로 진행한다. 로컬 모델을 선택하면 해당 실행도 별도 표시한다.
- 개발 중 유료 모델 호출이 필요하면 용도·모델·호출 수·최악 비용을 제시하고 별도 키·예산·사용 범위를 정한 뒤 진행한다.
- 키가 있다는 이유로 up/check/publish/verify-mvp/role-done이 자동으로 유료 호출하도록 구성하지 않는다.
- 실제 모델 평가는 승인된 데모 실행 범위와 예산 안에서 수행한다. 일반 테스트의 모의 결과로 실제 모델 검증이나 DONE을 대체하지 않는다.
- 계정 한도·사용 내역을 확인하려고 전달된 키로 API를 호출하거나 관리 권한이 있다고 가정하지 않는다.

## 프로모션 적용 상태

- 사용자가 전달한 계정 화면의 `Applied promotions / Amount / Date applied` 표기에 따라 **$50.00 크레딧이 2026년 9월 21일에 적용됨**을 기록한다. 이 세션이 계정에 접속하거나 직접 코드를 등록한 것은 아니다.
- 위 금액은 적용된 프로모션 금액이며 현재 남은 잔액을 뜻하지 않는다. `Date applied`는 적용일이며 만료일이 아니다.
- 실제 잔액·만료일·대상 조직/프로젝트·모델 제한과 기존 API 키의 연결은 미확인이다. 해커톤 안내와 계정 설정에서 확인한다.
- 프로모션 코드를 OPENAI_API_KEY나 모델 요청의 인증 헤더에 넣지 않는다. 코드 등록·크레딧과 API 키 인증을 구분한다.
- 크레딧 적용 표기만으로 기존 API 키의 데모 비용이 해당 크레딧에서 차감된다고 보장하지 않는다. 소진·만료 시 다른 결제 수단으로 계속 청구하도록 임의 설정하지 않는다.
- $50 크레딧 제공은 개발용 사용이나 사용 예산을 $50로 늘리는 허가가 아니다. 기존 데모 전용·$30 초과 예상 시 별도 처리 조건을 유지한다.

[OpenAI 공식 시작 안내](https://developers.openai.com/api/docs/quickstart)는 API 키 설정과 크레딧을 별도로 다룬다.
이 해커톤 프로모션의 구체적인 조건은 공식 공개 문서에서 확인하지 못했으며 별도 확인이 필요하다.

## $30 기준

사용자는 $30을 넘길 것으로 예상되면 별도 처리하기를 요청했다. 예산의 기간·공유 범위가 확정되기 전에는
이 데모의 누적 사용을 보수적으로 합산하며, 이 기준을 $30까지 개발에 써도 된다는 허가로 해석하지 않는다.
이번 작업의 사용자 키를 사용한 API 호출은 0회다. 계정 전체 사용액은 조회하지 않았다.

구현할 비용 제어:

1. 데모 모드·유료 호출 허용 설정·예산·모델 가격이 명시된 경우에만 OpenAI 호출 경로를 연다. 개발·CI의 기본값은 유료 호출 금지다.
2. 호출 전에 확정 비용 + 미확정 비용 + 진행 중인 호출의 예약 비용 + 새 호출의 최대 예상 비용을 합산한다.
3. $30 초과가 예상되거나 가격·사용량을 확인할 수 없으면 새 유료 호출을 시작하지 않는다. 별도 처리 계획을 기록한다.
4. 제한 시간·입출력 토큰·도구 반복·재시도·동시 조사 수를 함께 제한한다. 자동 상위 모델 전환으로 한도를 우회하지 않는다.
5. 예약·차감은 영속 저장하고 원자적으로 처리한다. 타임아웃·재시작 때 미확정 비용을 0으로 지우지 않는다.
6. 여러 PC가 같은 예산을 쓰면 공유 장부를 사용하거나 총합이 예산 안에 드는 PC별 한도를 배분한다. 각 PC에 $30씩 허용하지 않는다.
7. 한도·크레딧 오류는 무한 재시도하지 않는다. 실제 청구액과 추정액을 구분하고 초과 가능성을 숨기지 않는다.

OpenAI의 지출 알림은 호출을 차단하지 않는다. 별도의 프로젝트/조직 강제 한도는 호출을 차단하지만
집계·적용 지연으로 소폭 초과할 수 있다. 앱의 사전 예약과 안전 여유를 함께 사용하고,
월별 제공자 한도와 데모 기간의 누적 예산을 구분한다. 현재 계정의 한도를 설정하거나 확인한 상태는 아니다.
[OpenAI 지출 한도 공식 문서](https://developers.openai.com/api/docs/guides/spend-limits)

## 선택한 데모 방식 — 로컬 앱 + ngrok + OpenAI

사용자의 “엥그로드로 로컬에서 처리” 요청을 ngrok로 로컬 앱을 연결하는 방식으로 반영한다.
web·Spring Boot 세 앱·PostgreSQL·근거 볼륨은 시연 PC에서 실행하고, ngrok는 로컬 web의 HTTPS 진입점만 제공한다.
서비스 Agent는 로컬에서 조사·도구 실행·저장을 수행하고 모델 추론은 OpenAI API를 직접 호출한다.
ngrok를 모델 API 주소나 LLM 중계 서버로 설정하지 않는다. 로컬 LLM 전환은 이번 선택에 포함되지 않는다.

프로모션이 적용된 조직·프로젝트의 API 키를 로컬 Agent 실행 환경에 주입하면 같은 OpenAI 크레딧을 사용할 수 있다.
ngrok 사용으로 OpenAI API 사용량이 사라지지는 않는다. $50 적용 기록·데모 전용·$30 기준을 그대로 유지한다.
ngrok 계정·authtoken·이용 요금은 OpenAI 키·프로모션과 별개이며 OpenAI 크레딧으로 ngrok 비용을 충당한다고 가정하지 않는다.

브라우저 → ngrok → 로컬 web → 로컬 VOC → 로컬 Agent 순서로 연결한다. 쇼핑몰 요청은 web 서버가 로컬 commerce로 중계한다.
DB·Agent·commerce·VOC의 포트를 각각 공개하지 않으며 web에서 허용된 API만 중계한다.
OpenAI 키는 Agent에만, ngrok authtoken은 ngrok 실행 환경에만 둔다. 웹 번들·브라우저·터널 요청으로 키를 전달하지 않는다.
실행 순서·주소·검증·종료는 [ngrok 로컬 데모 절차](../ngrok-local-demo.md)를 따른다.

현재 Agent의 [명시적 데모 실행 설정](../../agent-app/README.md)은 구현됐다. 기본 유료 호출 금지이며 web·공개 터널·실제 모델 품질은 미검증이다.
[ngrok 공식 CLI 안내](https://ngrok.com/docs/gateway/agent/cli)에 따라 실제 계정·접근 제어·앱이 준비되면 실행한다.

## 인계와 확인 기준

Agent 구현 세션은 데모/개발 모드 분리·영속 비용 예약·유료 호출 금지 기본값을 구현하고 상태 문서에 보고한다.
VOC 담당자는 호출 제한·예산 오류를 정보 부족과 구분해 표시하고 재조사 버튼이 비용 제한을 우회하지 않게 한다.
일반 CI·빌드에서는 실제 키 없이 테스트하며, 유료 클라이언트가 한 번도 호출되지 않는지 검증한다.
동시 예약·미확정 비용·재시작·예산 소진은 합성 가격과 모의 모델로 검증한다.
데모에 사용할 모델·호출량·예상 최대 비용이 준비된 뒤 실제 실행 조건을 확인한다.
